# Canonical contracts and versioning

`contracts/foundation-v1.schema.json` is the single canonical transport schema, JSON Schema draft 7. Rust jsonschema validates that file embedded at compile time; Python Draft7Validator reads it directly; TypeScript/Ajv validates it at runtime and consumes types generated by json-schema-to-typescript. There are no independently maintained business DTO definitions in three languages. `npm run contracts:generate` regenerates types; `node scripts/generate-contracts.mjs --check` rejects drift.

The schema covers mode, HEALTH/ERROR/PING, UTC timestamp and UUID/correlation fields, source provenance, instrument identity, forecast horizon/probabilities, position intents, execution events, version references and public credential metadata. Source kind is FOUNDATION or FIXTURE in this version; no live-provider event is claimed ingested. Version is exactly 1.0.0. Unknown fields and event variants fail. UUIDs are canonical lowercase v4. Tenant/account IDs are required for private record kinds; authentication is not implemented.

Money, price and quantity use decimal strings: optional sign, at most 18 integer digits and 18 fractional digits, no exponent/NaN/Infinity. JSON timestamp units are integer milliseconds since Unix epoch, bounded within interoperable safe-integer time range. Chart internals convert their separate deterministic fixture timestamps to the engine's seconds; those are not transport DTOs. Probability components have numeric [0,1] bounds. Python rejects nonfinite JSON constants; TypeScript rejects nonfinite values; Rust's parser/schema rejects malformed nonfinite input. No floating-point financial arithmetic is introduced.

The forecast envelope is a shape contract, not probability calibration, normalization/label-maturity enforcement or trading logic. Cross-field probability sums, horizon-end consistency, positive risk quantities, actor authority and execution transition validity remain mandatory later domain validation. A shape-valid intent has no dispatch authority: no endpoint accepts position/execution/credential variants as commands. PING is the only accepted POST variant and its mode must match process configuration.

Representative valid/invalid cases live in contracts/fixtures.json and are consumed by all three languages. Private scope absence, unknown fields/version/mode, invalid instrument, malformed decimal and numeric bounds are covered. Passing these cases establishes wire compatibility, not future trading correctness. Additive/breaking schema changes require explicit versioning and fixture updates before release; this unreleased foundation schema was tightened for private IDs during completion. Existing Phase 1 requirement/test IDs remain unchanged.
