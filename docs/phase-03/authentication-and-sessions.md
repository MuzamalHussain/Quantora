# Authentication and sessions

Implementation: quantora_api/security.py, saas.py and saas_routes.py. All routes are under /api/v1/saas. Public operations: auth/csrf, register, login, recovery/reset or recovery/verify, reset, verify. Authenticated: auth/me, sessions, logout, logout-all, password and individual session deletion. No token or password is put in a URL, analytics or browser localStorage.

Accounts normalize email by stripping surrounding whitespace and lowercasing the whole ASCII address; Unicode email is deliberately unsupported. Unique Mongo email index prevents concurrent duplicates. Public registration always produces the same eligible/duplicate success wording and ignores no extra fields: role/tenant injection is rejected by strict input models. Passwords require 12–128 characters and at most 512 UTF-8 bytes. Argon2id uses argon2-cffi 25.1.0: 64 MiB, time cost 3, parallelism 4, 16-byte random salt and 32-byte output. Login checks the encoded hash; absent users check a dummy Argon2 hash. Passwords are never stored plaintext.

Sessions and tokens use 32 random bytes encoded URL-safe. Mongo stores SHA-256 hashes only. Each login issues a new random session, never adopts an incoming ID. Browser sessions have an eight-hour absolute lifetime; expiry is enforced in every server lookup independent of Mongo TTL timing. Session auth_version must match the current user. Password change requires the current password and revokes all sessions/tokens; password reset also revokes all sessions/tokens. Logout-all increments auth_version; individual revoke is scoped to the authenticated user. No role value from a cookie/body is trusted.

Cookies are HttpOnly, SameSite=Lax and Path=/. Local loopback HTTP explicitly uses Secure=false. QUANTORA_SECURE_COOKIE=true uses Secure and the __Host- prefix; invalid boolean values fail startup. No production-ready cookie/TLS claim is made. Mutations require exact Origin (127.0.0.1:5173 or :4173) and a random CSRF header matching the readable SameSite=Strict CSRF cookie. Authenticated mutations additionally match the CSRF hash held in the session. Fetching a CSRF token rotates that binding. CORS remains restrictive; the UI uses its same-origin proxy. X-Forwarded-For is not trusted for abuse identity.

Redis Lua atomically increments a fixed one-minute window: 30 requests per source address and eight per normalized account (or authenticated identity) for each abuse-controlled action. Registration, login, recovery, redemption and password change are bounded. Redis errors reject these operations with 503; there is no silent fail-open. Application request bodies retain the 4096-byte limit and three-second deadline. Network uncertainty after a write is not proof of rollback; durable idempotent operations can be retried with their original key.

Recovery/verification tokens expire after 15 minutes and are consumed inside the same Mongo transaction as the account mutation and audit. Atomic find-and-delete plus transaction retry prevents concurrent reuse. Password reset changes the auth epoch; verification does not create a login session. Recovery responses never return a token. MailDelivery is an interface; tests use bounded in-memory LocalMail, normal local use can configure EncryptedLocalMail. Its files are authenticated ciphertext under the separate server keyring, never public HTTP resources. `python -m quantora_api.manage read-local-mail` interactively asks email/purpose and displays a development token only to the local operator: do not capture that output in logs. No real external email was sent or deliverability tested. Production profile fails closed.
